# ADR-0001: フロントエンド統合ツールチェーンにVite+を採用する

- ステータス: Accepted
- 決定日: 2026-09-13

## コンテキスト

rendrilo はReactとTypeScriptで新規開発するクライアントサイドWebアプリケーションである。開発、ビルド、コード整形、静的解析、型検査、単体テスト、CIのために複数ツールを個別設定すると、設定の重複と更新作業が増える。

プロジェクトはまだ実装前であり、既存ツールからの移行互換性を考慮する必要がない。一方、Vite+は0.x系であるため、今後の仕様変更や周辺ツールとの互換性に注意が必要である。

## 決定

フロントエンドの統合ツールチェーンとしてVite+を採用する。

- UIはReact + TypeScriptとする
- 開発、整形、静的解析、型検査、テスト、ビルドの入口を `vp` に統一する
- パッケージ管理にはBunを使用し、Vite+経由で操作する
- Vite+とBunのバージョンをプロジェクト内で固定する
- CIでは公式の `setup-vp` GitHub Actionを利用する
- Playwrightなど組み込み外のタスクは `vp run` から実行する

## 理由

- 新規プロジェクトのため、既存設定の移行コストがない
- Vite、テスト、整形、静的解析、型検査を一つの設定と操作体系へ集約できる
- ローカルとCIのコマンド差を小さくできる
- React、Web Worker、WASMを利用する静的アプリケーションの構成と両立できる
- 必要になった場合も、標準的なVite構成へ戻しやすい

## 影響

### 利点

- 開発者が覚えるコマンドと管理対象の設定ファイルが減る
- 高速なRustベースの整形・静的解析ツールを利用できる
- ツール間のバージョン整合性を取りやすい
- CIの品質チェックを短い共通コマンドで表現できる

### 欠点とリスク

- 0.x系のため、アップデートで設定やコマンドが変更される可能性がある
- 個別ツールの高度な設定がVite+から利用できない可能性がある
- チームや外部コントリビューターが `vp` の導入を必要とする
- Vite+固有の問題が発生した際、情報や回避策が通常のViteより少ない可能性がある

## リスク軽減策

- バージョンを固定し、自動的なメジャー・マイナー更新を行わない
- ツール更新を独立したPull Requestとし、全品質チェックを実行する
- Phase 0でReact plugin、Web Worker、WASM codec、Playwright、CIを検証する
- アプリケーションコードをVite+固有APIへ不要に依存させない
- 設定で解決できない重大な互換性問題がある場合は通常のViteへ戻す

## 撤退条件

次のいずれかがPhase 0で解決できない場合、Vite+採用を再検討する。

- 対象ブラウザ向けWeb WorkerまたはWASMのビルドに重大な問題がある
- Playwrightを含むCIを安定して再現できない
- 必要な型検査・静的解析ルールを適用できない
- バージョン固定後も再現性を確保できない

再検討時は本ADRを `Superseded` とし、後継ADRに移行先と理由を記録する。
